\section{\texttt{honest-auth}: Admissible Capability Exchange \& The Trust Ladder}

\subsection{Why Bearer Query Strings Violate Admissibility}
In \emph{Reasons Are Not Permissions}~\cite{guimond2026reasons} and \emph{Reasonless Computation}~\cite{guimond2026reasonless}, an execution boundary is defined as a guard $\mathcal{G}: \mathcal{S} \times \mathcal{K} \to \{\text{Allow}, \text{Deny}\}$ that evaluates a structural capability token $\kappa \in \mathcal{K}$ orthogonal to the semantic payload. When a portal authenticates via \texttt{GET /?token=<bearer>}, the token $\kappa$ is embedded directly into the ambient Uniform Resource Identifier (URI). Because HTTP proxies, browser history stores, and \texttt{Referer} headers project the full URI onto untrusted logging sinks $\pi_{\text{log}}(\text{URI})$, the ambient authority leaks across security domains on the very first request.

\subsection{Zero-Leakage Bootstrap Nonce Scrubbing}
To eliminate ambient URI leakage while preserving single-click terminal launch convenience for \texttt{opencode.8b.is} and \texttt{dream.8b.is}, \texttt{honest-auth} enforces a three-phase state transition implemented in \texttt{HonestAuthGate} (\texttt{memnet/src/sovereign\_convergence.rs}):
\begin{enumerate}[leftmargin=1.4em,itemsep=1pt,topsep=2pt]
    \item \textbf{Single-Use Atomic Consumption:} A launch URL carries a 32-byte ephemeral bootstrap nonce $\nu_0$ with a hard time-to-live $\Delta t_{\text{TTL}} = 30\text{ s}$ and an atomic state register $\sigma \in \{\texttt{0:Unclaimed}, \texttt{1:Consumed}, \texttt{2:Revoked}\}$. Upon receiving \texttt{POST /\_honest/exchange}, the gate executes an atomic compare-and-swap:
    \begin{equation}
        \text{CAS}(\sigma, \texttt{0}, \texttt{1}) \;\wedge\; (t_{\text{now}} \le t_{\text{issued}} + 30).
    \end{equation}
    Any replay of $\nu_0$ (even within the same millisecond) sees $\sigma=\texttt{1}$ and is rejected with \texttt{NonceAlreadyConsumed}; expired nonces transition to $\sigma=\texttt{2}$ (\texttt{NonceExpired}).
    \item \textbf{Immediate URI Scrubbing:} The HTTP response returns status \texttt{303 See Other} (\texttt{Location: /}) alongside mandatory hygiene headers:
    \begin{itemize}[leftmargin=1.2em,itemsep=0pt,topsep=1pt]
        \item \texttt{Set-Cookie: \_\_Host-honest\_cap=<ticket>; HttpOnly; Secure; Path=/; SameSite=Strict}
        \item \texttt{Referrer-Policy: no-referrer}
        \item \texttt{Cache-Control: no-store, max-age=0}

    \end{itemize}
    On the client side, a minimal inline bootstrap script executes \texttt{window.history.replaceState(\{\}, '', window.location.pathname)} prior to mounting any workspace component or third-party asset.
    \item \textbf{Explicit Posture Disclosure (\texttt{X-Honest-Auth-Mode}):} In alignment with \emph{What the Trust Ladder Keeps Apart}~\cite{guimond2026trustladder}, every response header explicitly declares its active cryptographic rung (\texttt{TrustRung}):

        \mathcal{R}_{\text{trust}} \in \bigl\{\texttt{0:claimed},\; \texttt{1:attested},\; \texttt{2:sealed\_keyed},\; \texttt{3:hybrid\_pq\_bound}\bigr\}.
    \end{equation}
    A local development instance running at Rung 0 or Rung 1 is forbidden from masquerading as a production Rung 2/3 capability boundary.
\end{enumerate}

\section{Sovereign Per-Profile Inference: \texttt{AyeOS} Ternary Core + Keyed \texttt{DeepSeek-Engram}}

\subsection{Factoring Shared Reasoning from Personal Episodic Memory}
A naive multi-user deployment of a coding or dyad companion either (a) shares a single mutable memory pool across users---causing cross-tenant semantic contamination---or (b) duplicates the entire base model per user, exhausting host DRAM. Drawing on \emph{Amortized Deliberation}~\cite{guimond2026amortized} and \emph{Research Beyond the Token Budget}~\cite{guimond2026tokenbudget}, we factor the inference operator $\Phi_{\text{u}}(x)$ for profile $u$ into a shared, immutable 1.58-bit ternary reasoning backbone $\mathcal{W}_{\text{ternary}}$ and a compact, keyed per-profile N-gram memory vault $\mathcal{E}_{u}$:
\begin{equation}
    \Phi_{u}(x_t) = \mathcal{W}_{\text{ternary}}(x_t) + \alpha_{u}(t)\,\mathcal{G}_{\text{BFP64}}\!\bigl(\mathcal{E}_{u},\; h_{K_u}(x_{t-n+1:t})\bigr),
\end{equation}
where $\mathcal{W}_{\text{ternary}} \in \{-1, 0, +1\}^{D_{\text{out}} \times D_{\text{in}}}$ resides in shared read-only OS pages (\texttt{mmap(..., PROT\_READ, MAP\_SHARED)}) managed by \texttt{ayeosd}, and $\mathcal{E}_{u}$ is isolated inside a per-profile \texttt{SovereignProfileVault}.

\subsection{Keyed Lemire $p/q$ Multi-Head N-Gram Hashing}
In the upstream \texttt{DeepSeek-Engram} architecture (\texttt{workspace/Engram}), static N-gram lookups use unkeyed multiplicative-XOR hashes over prime-sized tables. In a multi-tenant environment, unkeyed hashing permits two attacks: (i) cross-tenant collision probing (timing which N-grams collide in cache) and (ii) precomputed algorithmic complexity DoS.

In \texttt{SovereignProfileVault} (\texttt{memnet/src/sovereign\_convergence.rs}), each authenticated \texttt{CapabilityTicket.sub} derives two domain-separated 256-bit keys from the master vault secret $K_{\text{master}}$:
\begin{align}
    \text{id}_{u} &= \text{H}_{\text{keyed}}(K_{\text{master}}, \texttt{"8b-sovereign-profile-id-v1"} \Vert \text{sub}), \\
    K_{\text{engram}, u} &= \text{H}_{\text{keyed}}(K_{\text{master}}, \texttt{"8b-sovereign-engram-key-v1"} \Vert \text{id}_{u}).
\end{align}
For each of the $H=4$ lookup heads with co-prime table capacities $P_h \in \{4093, 4091, 4079, 4073\}$, we extract a head-specific 64-bit odd multiplier $\mu_{u,h} = \text{LE64}(K_{\text{engram},u}[8h..8h+8]) \mathbin{|} 1$ and map the token N-gram $\mathbf{g} = (w_1, \dots, w_k)$ via Lemire's fast 128-bit $p/q$ range reduction ($q = 2^{64}$):
\begin{equation}
    \text{slot}_{u,h}(\mathbf{g}) = \left\lfloor \frac{\bigl(\text{mix}_{\mu_{u,h}}(\mathbf{g}) \cdot \mu_{u,h}\bigr) \bmod 2^{64} \cdot P_h}{2^{64}} \right\rfloor \in \{0, \dots, P_h - 1\}.
\end{equation}

\subsection{\texttt{BFP-64} Block Floating-Point Quantization \& Zero-Float Q16 Gather}
Storing $D$-dimensional FP32 embeddings requires $4D$ bytes per row ($256\text{ B}$ for $D=64$). Our \texttt{Bfp64Row} structure compresses 64 FP32 coefficients into exactly \textbf{65 bytes} ($3.94\times$ compression): a 1-byte shared biased exponent $e_b = \lfloor \log_2(\max_i |v_i| / 127) \rfloor + 127$ followed by 64 signed \texttt{i8} mantissas $m_i = \text{round}(v_i \cdot 2^{-(e_b - 127)})$.

Crucially, during multi-head Engram gather, we do \textbf{not} dequantize individual heads to IEEE-754 \texttt{f32}. Instead, \texttt{gather\_q16\_zero\_float} accumulates all $H=4$ heads directly in 32-bit signed fixed-point (\texttt{Q16.16}) using purely integer shifts:
\begin{equation}
    A_i = \sum_{h=0}^{H-1} \begin{cases}
        \text{i32}(m_{h,i}) \ll (e_{b,h} - 111) & \text{if } e_{b,h} \ge 111, \\
        \text{i32}(m_{h,i}) \gg (111 - e_{b,h}) & \text{if } e_{b,h} < 111.
    \end{cases}
\end{equation}
